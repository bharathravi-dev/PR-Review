- 2026-11-25 [event] Architecture run started (create). BMAD project config absent; skill defaults; manual append-only memlog.
- 2026-11-25 [constraint] Inherited from final PRD (prd-pr-reviewer-2026-11-24): one Review Engine shared by all Channels; FR-6a AI text-in/schema-out, no tools; FR-13 repo config limited to review-policy keys; FR-39 PR code executes only in a Sandbox; FR-19 idempotency via hidden marker; FR-20a pending reviews for review-requested PRs; release slicing R1 Engine+CLI, R2 Auto-Review, R3 Web App, R4 Extension.
- 2026-11-25 [constraint] Brownfield baseline: review.mjs zero-dependency Node ESM CLI (Node 18+), GitHub REST via fetch, single Anthropic call with forced tool, test.mjs; manual workflow_dispatch Action.
- 2026-11-25 [direction] Fast path; deliverable is the spine only (no additional human-facing rendering). Audience: maintainer + AI build agents.
- 2026-11-25 [decision] Paradigm: hexagonal (ports & adapters) around a pipes-and-filters Review Engine. Binds all packages. Prevents channels/validators reaching I/O directly or re-implementing review steps. Alternatives weighed: layered monolith (simpler, but channels would fork logic), microservices (too heavy for a solo maintainer + local CLI).
- 2026-11-25 [decision] Core is I/O-free and isomorphic: packages/core imports no Node built-ins (fs, child_process, net), no fetch, no process.env; all effects via ports. Binds core. Prevents a Node-only core that can't run in the R4 extension service worker (Standalone mode) and untestable engine logic.
- 2026-11-25 [decision] Dependency direction: channels → engine(core) ← adapters; adapters depend on core's port interfaces only; channels never import adapters' internals except through a composition root per channel; no adapter imports another adapter. Prevents cycles and cross-adapter coupling.
- 2026-11-25 [decision] Pipeline stages fixed and ordered: resolveConfig → fetchContext → detect → plan → execute(layers in parallel, per-validator timeout) → normalize → redact → dedupe/fingerprint → gate → assemble Report → publish(optional, separate step). Each stage takes and returns an immutable RunContext; only gate computes Overall Status. Prevents two channels assembling different Reports from the same inputs (NFR-8).
- 2026-11-25 [decision] Single schema source: zod schemas in core for Configuration (user + repo subset), Finding, Report, ValidatorResult, ProviderRequest/Response; JSON Schema generated from them and published; every artefact carries schemaVersion. Prevents drift between CLI JSON, Web App, extension, and validators' output shapes.
- 2026-11-25 [decision] Validator contract: {id, version, layers[], supports(ctx), needsSandbox:boolean, inputs(ctx)->declared file scope, run(ctx, ports)->ValidatorResult}; registered in a registry; ValidatorResult = layer statuses + Findings (schema) + tool name/version. Sandbox validators return results only as schema-validated JSON. Prevents ad-hoc validator I/O and unvalidated tool output (FR-39).
- 2026-11-25 [decision] Context retrieval: API-only (GitHub REST/GraphQL via GitHubPort) for metadata, diff, base+head file contents used by non-Sandbox layers; full shallow clone at head (plus merge-base) only inside the Sandbox. Resolves PRD OQ-8 "clone vs API-only". Prevents laptop runs needing a clone and untrusted checkout outside a Sandbox.
- 2026-11-25 [decision] Sandbox: SandboxPort with a container implementation (Docker or Podman CLI, auto-detected) running a pinned toolchain image; two phases: install (network to package registries) then analyze (network none); checkout copied in, no host mounts beyond a scratch dir, no env Credentials, results on stdout as JSON. In GitHub Actions (R2) the Sandbox is a separate job with permissions {} and no secrets. Prevents PR code touching Credentials (FR-39, NFR-1).
- 2026-11-25 [decision] AI boundary: ProviderPort.complete(ReviewRequest) -> ReviewResponse (JSON matching Finding schema). Adapters: anthropic-http, openai-compatible-http (OpenAI, OpenRouter, Ollama, Azure, custom FR-9a), claude-code-cli, codex-cli; later gemini, bedrock. CLI adapters spawn the vendor binary in a fresh empty temp dir with tools disabled, project settings off, minimal env (no GH tokens), stdin prompt, JSON-schema output. All responses re-validated by core (schema + file/line existence). Prevents agentic behaviour and provider-specific Finding shapes (FR-6a).
- 2026-11-25 [decision] Only the Publisher (core publish stage via GitHubPort) writes to GitHub; validators, providers, Sandbox get no write path. Prevents side-channel posts (FR-6a, FR-17).
- 2026-11-25 [decision] Credentials: CredentialPort resolves named Credential references (e.g. github, provider:<id>) from keychain, env, or vendor CLI (gh auth token); values travel as opaque Secret objects whose toString/JSON is redacted; logger redacts known secret values. Config holds references, never values. Prevents leaks into Reports/logs (FR-15, NFR-2).
- 2026-11-25 [decision] Idempotency key = sha256(owner/repo, pr number, headSha, configHash, engine major version). Hidden marker on every published summary and inline comment: HTML comment `<!-- pr-reviewer v1 key=<idempotencyKey> fp=<fingerprint|summary> -->`. The product identifies its own output only by marker. Prevents duplicate reviews and editing human comments (FR-19).
- 2026-11-25 [decision] Finding fingerprint = sha256(ruleId, normalized repo-relative path, normalized anchor text (anchored lines whitespace-collapsed) + up to 2 lines of context each side, source family) — never line numbers. Finding.id = fingerprint. Prevents duplicates across line shifts and across validators reporting the same thing (dedupe merges same fingerprint; cross-source merge by ruleId-category + range overlap). Resolves OQ-8 fingerprinting.
- 2026-11-25 [decision] "Unchanged inputs" for caching/incremental: validator cache key = sha256(validator id+version, tool version, resolved config subset the validator reads, git tree/blob SHAs of its declared input scope). AI cache key = sha256(provider, model, prompt-template version, redacted request). Re-review recomputes keys; cached results reused only on exact match; gate always evaluates the full PR. Resolves OQ-8.
- 2026-11-25 [decision] Auto-Review (R2) is stateless: GitHub is the state store. Discovery reads the user's own reviews (incl. pending) on each PR for the marker with the current headSha + configHash; present → skip. No separate state file/branch. Resolves OQ-8 state location. Prevents state divergence and PR data in automation logs/state (FR-29a).
- 2026-11-25 [decision] Auto-Review automation repo is private (created by setup in the user's account), schedule every 30 min + workflow_dispatch; discovery job (no checkout of PRs, no secrets beyond GH read token) → per-PR matrix: review job (engine, GH token, AI creds) and sandbox job (no secrets, permissions {}), results passed as artefacts validated by schema. Public repos rejected: workflow logs public and 60-day schedule disable. Resolves OQ-8 public vs private.
- 2026-11-25 [decision] Configuration files: user config `$XDG_CONFIG_HOME/pr-reviewer/config.yml` (macOS/Linux; %APPDATA% on Windows); repo config `.github/pr-reviewer.yml` read from PR base branch; YAML with `version: 1`; repo schema is a strict allow-listed subset of user schema; unknown/forbidden keys ignored and reported. Name tied to working product name. Resolves OQ-6 (subject to OQ-5 name).
- 2026-11-25 [decision] Report JSON (schemaVersion 1): run{id, idempotencyKey, repo, pr, baseSha, headSha, mergeBaseSha, configHash, engineVersion, channel, startedAt, finishedAt}, overallStatus, coverage[], technologies[{project, language, framework, version, confidence, evidence[]}], layers[{layer, validator, status, reason?, tool?, toolVersion?, durationMs}], findings[Finding per spec §23 + fingerprint], gate{result, failedRules[]}, ai{provider, model, usage{input,output}, costEstimate?}, rulesChecklist[], publish?{reviewUrl, pending:boolean, commentCount}, audit{...}. Timestamps ISO-8601 UTC; paths repo-relative POSIX. Resolves OQ-8 Report schema.
- 2026-11-25 [decision] Channels are thin: CLI, gh extension (shell shim invoking the npm CLI), Action (R2), Web App server (R3), extension (R4) each own only I/O, UX, and composition of adapters; none contains review logic. Prevents logic forks across channels.
- 2026-11-25 [decision] Monorepo: one repository, TypeScript, ESM, package-manager workspaces; packages: core, github, providers, validators, sandbox, cli, action (R2), web (R3), extension (R4); sandbox image built from this repo and published to a container registry. Brownfield: review.mjs retired after CLI parity (FR-16a); its rules/ migrate to Review Rules.
- 2026-11-25 [decision] Errors: adapters return typed results; infrastructure failures become Layer Status ERROR/TIMEOUT with reason, never Findings; engine never throws past a stage boundary except for programmer errors. Logging: structured JSON lines with redaction, level via config. Prevents mixed error semantics across validators.
