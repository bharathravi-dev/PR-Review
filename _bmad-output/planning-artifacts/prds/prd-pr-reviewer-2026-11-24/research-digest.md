## 2. Using a consumer subscription instead of an API key
**Claude Pro/Max**
- NOT ALLOWED: a third-party app that offers Claude.ai login, routes requests through Free/Pro/Max credentials for its users, or "collect[s], store[s], or intermediate[s]" Claude.ai tokens. Developers using the Agent SDK must use API keys. [V](https://code.claude.com/docs/en/legal-and-compliance), [V](https://code.claude.com/docs/en/agent-sdk/overview) (the Agent SDK note says "unless previously approved").
- GREY AREA, leaning allowed: our npm CLI shelling out to the user's own locally logged-in, unmodified `claude -p`. The policy says it does not prevent "an end user from signing in to the unmodified Claude Code binary with their own Claude subscription" [V](https://code.claude.com/docs/en/legal-and-compliance). Since 2026-06-15, `claude -p`, the Agent SDK and third-party tools draw on a separate monthly programmatic credit equal to the plan price (Pro $20, Max $100/$200) that does not roll over; after that, usage is billed at API rates [U](https://www.theregister.com/ai-ml/2026/05/14/anthropic-tosses-agents-into-the-api-billing-pool/5240748), [U](https://venturebeat.com/ai/anthropic-reinstates-openclaw-and-third-party-agent-usage-on-claude-subscriptions-with-a-catch/). Anthropic "may enforce without prior notice" [V](https://code.claude.com/docs/en/legal-and-compliance). This does NOT extend to the web app, the extension or a hosted auto-reviewer.
- ALLOWED: the user's own Anthropic API key, or Bedrock/Vertex/Foundry credentials [V](https://code.claude.com/docs/en/legal-and-compliance).

**ChatGPT Plus/Pro**
- ALLOWED: Codex CLI "Sign in with ChatGPT". `codex exec` reuses the saved login and supports `--json` (JSONL), `--output-schema` and a read-only sandbox by default. The docs still recommend API keys for automation and say to treat `~/.codex/auth.json` as a secret [V](https://learn.chatgpt.com/docs/non-interactive-mode). "Don't expose Codex execution in untrusted or public environments" [V](https://learn.chatgpt.com/docs/auth).
- ALLOWED WITH APPROVAL: the official "Sign in with ChatGPT" plan-usage OAuth for Responses API calls. It is open to all open-source partners and selected private clients; commercial use is a limited trial. Users set per-app weekly caps, and a backend code exchange is required [V](https://developers.openai.com/siwc/quickstart), [V](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites). Launched 2026-09-29 with 16 partners [U](https://thenewstack.io/sign-in-with-chatgpt/). This is the only sanctioned subscription path for the web app and the extension.
- GREY AREA: reusing the Codex OAuth token through a proxy, as community OpenCode plugins do. It is unofficial and could break [U](https://developer.puter.com/tutorials/openai-oauth/).

**Other options**
- GitHub Models: NOT AN OPTION. It was retired on 2026-07-30 (API, catalog and BYOK endpoints) [V](https://github.blog/changelog/2026-07-30-github-models-is-now-retired/). We found no sanctioned API for third parties to use a Copilot subscription [U: not found].
- Gemini CLI: Google-account sign-in for individuals and Google AI Pro/Ultra stopped serving on 2026-06-18 (replaced by Antigravity CLI); Gemini API keys still work [V](https://developers.googleblog.com/en/an-important-update-transitioning-gemini-cli-to-antigravity-cli/). The free API-key tier was ~250 requests/day on Flash only [U](https://geminicli.com/docs/resources/quota-and-pricing).
- OpenRouter: ALLOWED. OpenAI-compatible API at `https://openrouter.ai/api/v1`, with BYOK provider keys and routing [V](https://openrouter.ai/docs/guides/features/compatibility), [V](https://openrouter.ai/docs/features/byok).
- Ollama: ALLOWED. Local OpenAI-compatible API at `localhost:11434/v1` [V](https://docs.ollama.com/api/openai-compatibility). Calling it from the extension requires `OLLAMA_ORIGINS=chrome-extension://*` [U](https://objectgraph.com/blog/ollama-cors/).

## 3. Automatically reviewing every PR on "my account"
- GitHub App: needs an org owner to install it (or a repo admin, unless owners restrict that). Members can only *request* installation [V](https://docs.github.com/en/apps/using-github-apps/requesting-a-github-app-from-your-organization-owner). Even a user token issued through the App only reaches accounts "where it is installed" [V](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/authenticating-with-a-github-app-on-behalf-of-a-user). So it works for the user's own repos, not for third-party orgs.
- Reusable Action: needs write access to add a workflow file, plus a repo secret. Secrets are not passed to workflows on PRs from forks [V](https://docs.github.com/en/enterprise-server@3.17/code-security/reference/secret-security/understanding-github-secret-types), [V](https://github.blog/2020-08-03-github-actions-improvements-for-fork-and-pull-request-workflows/). So this doesn't work for a contributor's PRs in a third-party org.
- Repo webhooks: need repo admin [V](https://docs.github.com/en/webhooks/types-of-webhooks).
- Polling with the user's own token: run `search issues is:pr author:@me` (or `gh search prs --author @me`), then post the review as the user. The search API allows 30 requests/min when authenticated [V](https://docs.github.com/en/rest/search/search). This is the only option that reaches repos the user doesn't administer. Limits: an org can require owner approval for fine-grained PATs or block classic PATs [V](https://docs.github.com/en/organizations/managing-programmatic-access-to-your-organization/setting-a-personal-access-token-policy-for-your-organization), and OAuth-app access restrictions are on by default for new orgs [V](https://docs.github.com/en/organizations/managing-oauth-access-to-your-organizations-data/about-oauth-app-access-restrictions).
- How comparable tools handle this: Copilot has a per-user setting that auto-reviews PRs you create "in any repository where Copilot code review is available", but the org must allow it [V](https://docs.github.com/en/copilot/how-tos/copilot-on-github/set-up-copilot/configure-automatic-review). CodeRabbit's `--remote` review requires its GitHub App [V](https://docs.coderabbit.ai/cli/index). PR-Agent's CLI runs with the user's token [V](https://raw.githubusercontent.com/qodo-ai/pr-agent/main/README.md). Qodo's extension needed its App installed for private repos [V](https://docs.qodo.ai/v1/integrations/chrome-extension).

## 4. Chrome extension (MV3)
- Remote code is banned: no remotely loaded scripts and no `eval` of fetched strings. Calling remote servers is still allowed, including "performing server-side operations with data" and fetching remote configuration [V](https://developer.chrome.com/docs/webstore/program-policies/mv3-requirements). Prompts and rules can be fetched as data, but must not be executed as logic.
- Network: the service worker can fetch from cross-origin hosts declared in `host_permissions`; content scripts cannot. Relay requests through the background with narrow, validated inputs [V](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests).
- Calling AI APIs directly (BYOK) works. Anthropic requires the `anthropic-dangerous-direct-browser-access: true` header, and the key is visible in devtools, so this is acceptable only for the user's own key [U](https://simonwillison.net/2024/Aug/23/anthropic-dangerous-direct-browser-access). The ChatGPT plan-usage OAuth needs a backend code exchange [V](https://developers.openai.com/siwc/quickstart). Claude subscription OAuth is not permitted at all [V](https://code.claude.com/docs/en/legal-and-compliance).
- Storing keys: `storage.local`/`storage.sync` are exposed to content scripts by default (use `setAccessLevel`). `storage.session` is in-memory, hidden from content scripts, and cleared on browser restart [V](https://developer.chrome.com/docs/extensions/reference/api/storage). Chrome Web Store policy treats authentication info as sensitive and requires HTTPS, encryption at rest (AES/RSA), a privacy policy and prominent in-UI consent [V](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq.md.txt).
- GitHub DOM: the new "Files changed" page has been the default since Jan 2026. Its routes redirect to `/changes`, it navigates between tabs without full page reloads, and large PRs render through virtualization [V](https://github.blog/changelog/2026-01-22-improved-pull-request-files-changed-page-on-by-default/), [V](https://github.blog/changelog/2026-02-05-improved-pull-request-files-changed-february-5-updates/). Fetch PR data through the REST API, render our own panel, and use a MutationObserver with defensive selectors.
